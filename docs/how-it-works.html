The rules, in order

  1. Needs no testing. Documentation only (Documentation/, lustre/doc/, contrib/, *.md, *.txt, README, LICENSE, ChangeLog), or a patchset whose code Gerrit says is unchanged from the last one (only the commit message changed; the code was tested already): trivial alone, nothing else.
  2. Mandatory test sets. Each code area in the table below has test sets that belong to it. A patch touching the area runs them, whatever the history or the budget says. Test scripts are not an area's code (sanity-hsm.sh does not make a patch an HSM patch): the next rule covers them.
  3. Edited tests. A patch that changes only test functions of test scripts (no helpers, not test-framework.sh, cfg/ or functions.sh) runs just those tests: testlist=<script> env=ONLY="<tests>". Any other change to a test script runs the whole script.
  4. The patch-blind base. The first 17 test sets of the order below, the same for every patch: the most that keeps trivial plus the base within 25% of today's session time. Skipped when the patch changes only test scripts: it cannot break Lustre's code, only those scripts.
  5. History. Every test set that caught a bug on the last faulty patchset of the same change runs again. Older history re-runs tests for bugs since fixed (E7).

A test set picked twice runs once; test sets in one configuration share a session. trivial always runs, and Autotest still runs its subtest-change sessions for edited tests.

Bugs caught against cost

trivial and Autotest's subtest-change sessions alone cost 10% of today's time and catch 49% of the bugs. Every selection starts there, the oracle included, which is why its line rises straight up from that point.

Bugs count per change, every bug of a patchset. A test set catches a bug with the chance it failed with it when it ran. The oracle knows each patch's bugs and picks the cheapest tests that catch them; nothing can beat it.

The cost model

  • Session setup: 22 minutes per session (node provisioning and Lustre initialization), paid once per configuration a selection uses.
  • A test set: the mean time of that script in that configuration, from finished review sessions since 2026-03-20. An ONLY= line costs that times the share of the script's subtests it asks for.
  • Always run: the trivial session (4.6 hours) and Autotest's subtest-change sessions when a patch edits tests.
  • Today: every session the patchset's build ran: 118.2 hours on average over 2,129 randomly sampled patchsets.
  • Budget: the base is cut where trivial plus the base would pass 25% of today's time. Mandatory sets, edited tests and history come on top.

Patch risk

A separate score: how likely the patch is to carry a bug CI would catch. A logistic model on patch signals (signals/), fitted to the population (base rate 19%). High from the 85th percentile of patches (a score of 33%), medium from the 50th (12%), low below. It does not change the selection; it is for routing review.
