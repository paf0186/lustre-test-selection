How much testing does a patch need?

Backtest on 291 faulty patchsets the predictors never saw (changes first failing on or after 2026-08-01), holding 476 bugs. Today every patch runs the whole review matrix, about 135 session hours per build. "Share of today's bugs" is what each selection would catch of what today's matrix catches, with every change counting once.

  • 90% at 25%: not met yet. Best within the cost: + principles and directory history, 30%, 68% of today's bugs at 23%.
  • 90% at 10%: not met yet. Best within the cost: trivial only, 35% of today's bugs at 9%.
  • 95% at 10%: not met yet. Best within the cost: trivial only, 35% of today's bugs at 9%.

How this is measured

  • Bugs: a patchset's patch faults grouped by error signature across scripts; a failure over most of the scripts its build ran counts as one cascade; bugs no selection could tell apart (same scripts, same configurations) count as one. The label audit (eval/audit) checks the grouping and the labels.
  • Each change counts once: a change whose patchsets fail hundreds of tests weighs no more than one that fails one. The per-bug figure is in the table.
  • A selection catches a bug when it runs a script in a configuration where that script failed with the bug in the patchset's own build, with the chance the build showed (failed runs over runs). A configuration where the script never ran counts as not caught.
  • Trivial (review-ldiskfs) and the subtest-change sessions run for every selection and are charged to it.
  • Cost is session time on a random sample of all review patchsets: 23 minutes of setup per added session plus each script's mean run time in its configuration.
  • Single-MDT, Ubuntu and SLES client configurations are asked for with keys no custom session has used yet; SELinux, shared-key and IPv6 configurations can only be asked for as whole groups.
